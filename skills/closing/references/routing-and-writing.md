# 有价值残留的分流与落盘

仅在存在需要保存、裁决或归位的有价值内容时读取。先核既有决定与落实证据；无候选不读本分支，无新价值不另建记录。

## 提取心法（贯穿沉淀路由，先于分流）

提取规则不是为了约束（constrain）AI，而是为了让 AI **更懂人、更懂场景、更好配合**。

> 遇到输出体验类反馈（表达方式、格式、语气、阅读负担等），先理解背后的真实用户需求和个人背景，再决定沉淀什么。不要机械拆成“禁止做什么”的清单；记需求与场景，而非堆禁令。
> 规则是否入库、升格或改变默认行为，按当前工作区适用的规则治理与入库约定执行；涉及现行规则或长期默认行为的修改，继续遵守对应确认闸。

## 项目分流（复用当前工作区的项目路由）

`closing` 是收尾检查器和残留分流入口，不是新的项目路由真相源。首次确定去向、项目身份或路由发生变化、归属不清时，按以下顺序定向核对。已核验且未变的项目与落点直接复用，维护已确定的既有记录不重读全量分流材料：

1. 使用当前工作区已有的项目台账或项目入口确认项目身份、当前物理路径和生命周期，再用文件现场复核；台账不替代目录、Git 或运行环境证据。
2. 根据当前工作区已有的内容归属与路由约定判断内容性质和唯一项目去向，不在本协议重建项目映射表；没有相关约定时沿用已确认的所属项目，归属不清则先询问。
3. 读目标项目 `AGENTS.md`、更新规则或主索引，确定现行入口、候选边界、变更记录和验证要求；冲突时目标项目规则优先。

收尾只补以下纪律：

- 一段混合内容先拆成原子条目，每条只有一个正式落点；已归位内容不重复搬运。
- 决定、必要证据和接续信息按内容性质复用现有案例、任务或治理记录；具体商品、图片或单次任务经验留在所属项目的现有案例或任务记录，不默认写入 Skill；不新建重复候选库、日志或进度表。
- 需长期复用的经验，同时明确保存位置和未来任务的现行读取入口。未落盘、路径不可用或读取入口未验证时，分别如实说明，不以文件存在代替接通验收。
- 长期行动只进唯一牵头项目现有的待办记录；牵头未定、尚未拍板的规划或模糊想法仅按用户明确授权保留在既有暂存位置，否则在对话中说明，不复制到多个清单。
- 跨项目 AI 协作规则和长期默认行为按当前工作区的治理约定处理；只对单一项目有效的规则归该项目的规则入口。
- 尚未建立的 Skill 候选，只有用户明确选择保留后才进入已有候选记录，同时标明“通用”或“项目专属”的拟归属。建立后按当前工作区约定维护唯一正文与发现入口，不复制正文或为收尾另建管理体系。
- 临时单工具 memory 不是正式项目落点、不是 canon，用前必须核实；具有正式价值的内容仍按当前工作区已确认的项目路由归位。
- 项目、性质或适用范围仍不清时标 `UNKNOWN`，报告老板一次；裁决前不猜、不写草稿或正文。

**背景资料归口：** 公司或个人背景资料按当前工作区已确认的归口保存，不把本 Skill 当作背景资料库，也不将敏感原始资料复制到多个项目。来源中已有用户明确裁决且无更晚冲突的，按目标库规则处理；未经裁决的只报告一次，用户选择“留待核”时才按授权保留。

## 方法与工具改进（并入残留分流）

交互收尾按入口“未完与阻碍”区分当场处理与另开接续。本任务发现有依据、能明显改善结果或减少返工和人工负担的方法或工具问题时，优先完善现有 Skill、MCP、CLI 等能力；说明具体改动、收益、影响及验证办法，并入同一次候选讨论，按授权落实。

- 现有规则或工具用法合理但未执行 → 纠正使用、执行与检查，不新增同义规则或据此修改工具。
- 规则本身造成不必要阻碍 → 可提出精简、合并、修改或删除，指出具体条款、影响及需保留的安全边界。
- 现有工具存在缺陷或能力缺口 → 优先作为该工具的完善候选，按工具所属项目或维护渠道的现行规则处理；受工具或环境限制时给出可行替代及必要的最少人工操作，不把 AI 可完成的工作转交老板。
- 现有 Skill 覆盖不了，且重复出现或单次 ROI（投入产出比）明显 → 作为新 Skill 候选，并先判断通用或项目专属归属。
- 普通工作步骤、AI 常识、重复、缺乏依据或没有长期价值的内容 → 静默不存。

涉及 Skill 的具体治理，按需读取当前工作区已有的 Skill 维护与创建约定；没有约定时提出建议供用户决定，不自行建立长期规则。

## 落盘计划字段

- 每条写清：存什么、目标项目 / 文件、动作类型（新建 / 末尾追加 / 维护既有内容 / 删除候选）、候选或现行状态、是否已在本轮即时落盘。
- 维护既有内容时补充：冲突点、影响范围、保留 / 删除理由、当前文件指纹或并发检查、回滚方式和验证动作。
- 一般目标文件在计划确认前不写；本Skill方法经验可按入口的成长机制自动留证，不升为规则。符合[清退分支](cleanup.md)且当前用户已有授权明确覆盖的交互收尾清理，无需重复申请同批授权；无授权时先确认具体范围。用户已经确认具体批次后，不重复增加第二道同义确认。删除重要文件、外部发送和真实系统写入仍按其独立确认闸处理。
- 能否落盘由当前工具能力决定；读不到或无写权限时只给建议或精确补丁，不冒充已同步。
- 注入防护、敏感信息和外部动作风险处置沿用当前工具上级规则，本协议不重写。
