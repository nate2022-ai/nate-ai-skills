# 自动化复盘

仅供已有复盘自动化调用；读取本分支不授权新建、恢复或改动排程。

## 自动化复盘模式（非交互收尾）

当已有且获授权的工作复盘自动化读取本协议时，只吸收真正影响长期沉淀质量的内核：价值过滤、按内容性质拆分、项目路由、来源与冲突核对、敏感检查、Skill 缺口判断。

- 只提取长期有价值的结论、老板决策、规则或事实变化、可复用且有结果证据的方法、仍未完成的长期事项；普通调试、重复内容、已被证据否定的结论、长日志、完整对话和失败过程细节不沉淀。
- 不执行交互收尾五项展示，不生成完整过程复盘、下一任务提示词或强制下一步；不执行交互收尾的全量脚手架清退。只有调用自动化已明确授权时，才可清理本轮自身创建、归属明确、已无引用、非现行真相源、非回滚证据且不含用户既有未提交内容的临时文件、一次性脚本和预览脚手架；其他只列候选。
- 先按调用方提供的项目入口和真实目录核对项目职责，再按当前工作区已有的内容归属约定判断去向；一段混合内容拆成多个原子条目，每条只有一个正式落点。
- 定期复盘负责查漏与跨任务归纳，先核对既有收尾记录中的决定、落实证据和未完成项。无新冲突或范围变化时，已裁决的不重问，已落实的不重复执行；已确认未落实的，按有效授权接续或说明待办。新候选报告一次、回答后当场处理；冲突或范围不清由老板一次裁决；重复或无价值静默丢弃；草稿只在老板明确选择“留待核”后写入。
- 审核项不设数量上限。降噪依靠价值过滤、语义去重和同类合并，不得因固定上限漏掉真正需要判断的内容。

存在有价值候选需要判定或落盘时，再读[routing-and-writing.md](routing-and-writing.md)。自动化首次路由核验及后续刷新遵守调用方明确提供的治理约定；已有且未变的路由证据直接复用。缺少必要路由或写入授权时，只报告待核事项。
