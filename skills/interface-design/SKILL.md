# 界面设计 · Interface Design

以Apple设计知识为主要母本，结合成熟设计方法，让AI理解设计意图、作出有理由的选择、完成高质量界面，并从真实结果纠偏。设计质量同时包括视觉表达、易理解与易操作、可靠性、平台适用性和维护成本。

内部标识为`interface-design`，Codex中文入口为“界面设计”。跨平台方法已纳入，平台实现验证分别留证；方法覆盖不代表所有平台已验证。安装、工具条件和自定义方式见[README](README.md)，知识来源及采用边界见[来源与转化](references/sources.md)，不要求普通任务先读安装或来源报告。

## 任务与结果

沿用户当前请求和已有授权选择工作方式，可以组合，不固定跑完全部方式：

| 请求 | 工作重点 | 应交结果 |
|---|---|---|
| 新设计 | 理解内容与使用方式，形成整体结构和视觉方向，再具体化状态与操作 | 可判断的草稿、关键取舍；获准后完成实现与对应验证 |
| 审查 | 看真实界面、任务和已有实现，找有效部分与影响使用的问题 | 准确位置/条件、影响、依据、建议与优先级；审查本身不授权修改 |
| 改造 | 复用仍成立的方向和证据，修正真实问题，维护整体一致性 | 实际变更、前后对照与相关回归结果 |
| 验收 | 在目标环境走任务、看整体质量，对照承诺与事实 | 通过范围、未通过项、未验证项及必要证据 |
| 找设计参考 | 按当前任务查设计奖、获奖网站及优秀产品的相似案例，核身份并看实际界面 | 可打开的来源、相似理由、可借鉴方法与适配限制；是否实施沿当前授权 |

设计稿、代码检查、运行交互、业务体验是不同证据。任务只要其中一项时完成该项，清楚说明能证明什么。

## 核心理解：先会判断，再查细节

### 任务决定信息关系

从“谁在什么条件下，要判断或完成什么”理解界面。明确用户需要识别的对象、共同阅读或比较的信息、当前状态、下一步及失败后的去处。依据先从项目和现有任务找，只有会改变方案且确实缺少的信息才问。

突出程度综合考虑下一步决策、误判后果、操作频率与发现难度。低频但后果严重的警告不能因“低频”隐藏。信息密度是同屏有效关系的数量；增加留白或减少内容都不自动等于更好。

例如，浏览参考图时图像可以主导；按款号精确查找时，编码与匹配理由需要容易识别；跨店铺比较出库量时，同行同列的对齐关系比把每条记录变成大卡片更有价值。一次用户反馈沿其场景使用，不直接写成全局禁令。

### 整体视觉有方向，细节有关系

从内容、受众、品牌、场景和平台形成一个具体视觉意图，例如“便于长期阅读的精密工作台”或“以作品和材料质感建立信任的展示界面”。把意图落实为构图、排版、图像、色彩、表面和交互的共同选择，不能只贴风格形容词。

主次可以通过位置、尺度、字重、对齐、间距、色彩与层次共同表达，避免每处都强强调。读完局部后回看完整页面：重心、节奏、内容比例和组件语气是否协调。审美应在方案形成时参与，不能留到功能结束后加装饰。

Apple的清晰层次、连续反馈和平台适配提供判断依据；品牌表达与场景可以有自己的形态。复用现有组件前核是否适合；已知业务事实、权限和已确认要求保持准确，旧界面没有天然设计优先权。

### 继承认可的整体，局部调整回看完整路径

用户已认可的构图、层级、入口关系和交互可作为本次基线。后续补分类、字段或缩小比例时，保留这些有效关系；新细节改变重心或操作顺序，先回到完整页面判断。用户说某处“不标准”或“太大”，不直接转成全页改轴、禁用卡片或缩放整页。

工作网页默认从紧凑、有主次的表达起步：图形帮助识别类别，文字卡片选择具体对象，行列关系比较数值。需要连续阅读、大图识别或使用者另有偏好时按任务调整密度；展示网页根据内容、品牌和受众灵活定方向。具体配色、分类名和像素属于项目选择，不能随方法推广到所有页面。相关表达见[视觉与设计系统](references/visual-system.md#紧凑工作网页的表达)及[查找与对象选择](references/information-patterns.md#查找与对象选择)。

### 操作可预期，状态可解释

让用户理解哪里能操作、作用于谁、执行后会发生什么。输入、展开、选择、提交与导航用与其语义一致的控件和反馈。重要状态使用文字、位置或图形共同表达，避免只靠颜色或动效。

把正常、等待、空、失败、权限与恢复放进相关主流程：筛选无结果与网络失败不能同写“暂无数据”；保存成功必须对应真实成功；选择范围和批量影响不能靠用户猜。并非每项任务都要制造所有异常，只补实际可能且影响结果的分支。

### 平台适配保留任务与连续性

先核可用窗口、内容规模、输入方式、字号设置及运行平台，再选布局和组件。跨平台复用的是对象含义、任务关系、视觉角色和状态模型；具体导航、手势、单位及系统交互按平台处理。

缩小空间时优先重排、改变同时展示的区域或按需展开，保持选中项、输入、筛选和返回位置等任务状态。大屏可增加有效比较和并列上下文，而非把内容整体拉宽。窄浏览器截图不证明手机触控或原生应用可用。

## 如何完成任务

### 理解现场与定方向

先核任务对象、现行代码/设计稿、用户目标、真实内容和平台条件；不要让整理资料代替看现场。区分信息/视觉问题与数据、权限、业务流程或性能根因。已有有效结论直接沿用，局部修复不重新设计全站。

AI先给有依据的推荐。只有现有信息无法解决且会显著影响结果的取舍，才提供真正不同的备选。草稿展示足以判断的布局、信息主次、视觉方向、关键操作、必要状态与尺寸差异；已有工作台保留影响判断的总导航和所在模块。

用户要求参考设计奖、获奖网站或相似案例，或当前方案确实缺少可判断的参考时，按[设计案例检索](references/design-case-research.md)查找并观察相关作品。先匹配任务、信息与交互，再看风格；奖项身份和对当前项目的适用性分别判断。局部调整已有充分依据时无需重新搜案例。

实际应用新的或主要调整过的界面方案前，给用户确认具体草稿；使用项目有明确约定时沿其有效约定执行。已确认且范围未变的草稿直接沿用；普通样式细节和对应修复在原授权内完成。改变主要布局、信息主次、关键交互或视觉方向，先更新草稿再确认。纯审查、隔离试验及只交草稿时按其自身范围执行。

### 形成可实现的表达

根据目标和实际内容选择视觉角色、布局关系、组件及交互状态。参数需要具体可执行：给出有条件的初始值并检查实际字体、内容和设备，不永远只写“适当”。来源建议、平台规范、项目选择及试验值分别说明。

在现有技术和数据边界内实现。新增或替换组件体系须有具体收益与迁移范围，不因读到某个参考就增加依赖。图像、字体和图标使用真实可用资源；占位和模拟内容明确，不能改写成业务事实。

复杂任务可以先跑通一条端到端主流程，再扩展相关状态与页面；简单改动直接完成。保持工作台公共壳与内容一起可用；不覆盖并行修改者的文件。

### 看实际结果并交付

检查这次选择是否兑现：任务能否完成、事实是否保持、状态是否一致、视觉整体是否协调、目标输入方式是否可操作、相关尺寸与文字变化是否适配。复核已发现问题以及受影响的相邻流程，规模随风险取舍。

用对应运行版本留证，不能用旧截图证明新代码。未运行就报告静态核查；缺目标设备、数据或工具时完成可行部分，明确证据限制。检查通过的页面可在该条件下成为参考，不推导全平台通用。

交付用用户能理解的语言说明结果、关键理由、验证和剩余问题；文件与证据放在负责项目已有位置，不固定附长报告、评分或成本表。

## 反馈与演进

对有复用价值的反馈先归因：设计知识、Skill表达、执行偏差、业务资料或运行环境。项目实例和原始证据沿该项目已有验收/案例记录；通用方法经验沿维护项目指定的经验入口保存和按问题读取，引用已有证据而不重复保存。没有配置保存位置时，在当前交付中说明发现，由使用者选择去处，不因缺少私人资料库阻塞设计。

普通任务无需读取全部历史。维护时保留有效条件和反例，合并重复，淘汰造成负担的旧限制。在已明确批准的改进范围内，完成对应问题验证并核相关退化后按该范围更新，保留依据、准确版本与恢复内容；扩大采用范围、改变核心方向或超出既有授权的正式改进，提出具体差异交维护者决定，并遵守所在项目的治理要求。来源原文不随我们的方法改写。一次好评不代替验证，持续成长不自动授权后台监控或新任务。可公开的编制经验见[研究过程](research/design-method-evolution.md)，它提供背景，不是每次任务必读的指令。
