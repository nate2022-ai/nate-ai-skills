# 视觉与设计系统

适用：形成或打磨整体视觉、排版、颜色、图像、材质、参数和组件。以下是首版整合方法，项目参数示例不等于Apple标准；来源与读取边界见[sources](sources.md)。

## 从方向到可见选择

先辨认内容的视觉重心：作品、文字、数据、工具还是连续操作。把目标转成可观察的选择，例如“精密、克制”可以体现为稳定对齐、有限强调色、可比较数值和细致状态；“富有材料感”可以体现为真实图像、光线与留白关系。不要把气质简化成一种字体或玻璃效果。

选择一个主导方向，内部保持足够变化：标题与正文、背景与内容、主操作与辅助操作应有区别；页面之间保持同一种视觉语言。用内容本身、构图、字体角色和图像表达个性，不依赖到处增加装饰。既有品牌与用户已确认偏好沿用其范围。

视觉审查从全局到局部：远看重心与节奏，中看分组与比例，近看字形、对齐、图标和状态。功能可用不能替代整体品质，截图漂亮也不能证明可操作。

## 排版与阅读关系

按用途定义文字角色，如页面标题、区域标题、正文、数据、标签、辅助信息；用字号、字重、行高、颜色及间距共同建立区分。相同角色共享规则，有意义的强调可单独处理。

中文选择实际具有中文字形的字体栈，检查系统回退后字重是否仍有层次；不能只用英文标题选字体。中英文、单位、日期和编码用真实长度检查换行、基线及辨识。中文默认不套拉丁大标题的强负字距，短标签也不为整齐删掉关键含义。数字比较可使用等宽数字特性；编码更关注0/O、1/l等辨识，不必把整页改成等宽字体。

连续阅读控制行长和段落节奏；表格通过列对齐与行间关系提高扫描效率。辅助说明可以弱化，不能因颜色浅或字号小到无法理解。文本放大后保持角色层级，允许容器增长；固定高度和截断前检查能否取得完整内容。

参数落地时选实际字体和目标窗口，用长标题、大数字、空值和换行验证。示例起点：普通中文Web正文可从16px、1.5倍行高试起；密集工作台、展示标题或原生文字样式另行选择。这是试验起点，不是下限或全局要求；系统字号设置与用户放大优先保留。

## 间距、密度与构图

间距表达关系。组内距离通常小于组间距离，但标题、图像和工具栏的视觉重量会影响实际感觉。建立少量可组合的间距层级，同时允许光学修正；不必为了数列整齐强制每个距离都是同一倍数。

密集界面优先减少无效容器、重复标签和装饰，保留可点击区域与清晰分组。内容少时可以扩大作品展示或用说明建立意义，不能用空白伪装丰富。大屏通过内容最大宽度、并列区域或列密度组织空间；窄屏按任务重新分配，而非等比缩放。

图像边缘、字形和图标可能需要视觉对齐而非数学居中。圆角与边界由组件尺度和用途形成家族关系，不要求卡片、按钮、输入框统一一个值。

## 紧凑工作网页的表达

当使用者明确偏好紧凑工作台时，先减少重复标题、无效空白和装饰面积，再检查正文与点击区域。图形可以突出大类，子级图标或文字卡片承担具体选择，数字与单位负责精确判断；每一级不必使用相同体量的图片。层级由尺度、内容和关系表达，三级对象同样可以块状显示。

缩小图片时回看一级与二级的相对视觉重量，避免子级反而主导页面。名称是主要识别依据时，将型号、日期、记录数等放在辅助位置；比较时让共同字段对齐。保持同一组件语气，比把每个内容都做成同一种形状更有价值。品牌、作品或商品展示可另选构图与留白，不机械沿用工作台密度。

## 颜色、图标、图片与材质

颜色先表达角色：主要文字、次要文字、背景、表面、边界、强调、状态。跨页面复用语义，主题切换分别定义，不机械反相。状态不能仅靠红绿区分；文字、图形或位置应补充意义。对比度在实际组合和背景上测，不凭色值名称判断。

选择图标时统一视觉重量、尺寸与基线，陌生或歧义动作保留标签。装饰图标不应抢占正文；图标单独作按钮仍要可辨认的名称和操作区域。使用可获得且许可适用的图标集或项目已有资源，不假设SF Symbols可直接作为任意平台素材分发。

图片是内容时保留身份、比例、关键细节和来源关联。裁切应服务任务：情绪展示可以取景，商品识别不能裁掉所需特征。为缺图、加载失败、不同纵横比设计稳定布局，不将演示占位当正式资源。真实产品图片不凭空补造事实。

材质帮助解释前后层级与聚焦关系。导航或浮层可在符合平台与任务时使用透明、模糊和阴影；长文、密集数据或复杂背景需要稳定可读的表面。检查深浅背景、滚动、降低透明度设置及设备性能。Liquid Glass等平台语言需要对应平台条件，不直接成为所有容器的默认皮肤。

## Parameters → Tokens → Components → Patterns

把已选择的参数按角色集中表达。基础值描述尺度和色值；语义Token说明用途，如text.primary、surface.overlay、action.primary、space.group；组件使用这些角色并补充必要状态。无需为了层次完整建立三套独立文件。

例如同一个action.primary在浅色/深色主题对应不同颜色，但“主要操作”含义不变。跨平台可以共享这个角色，Web输出CSS变量，原生映射系统颜色/文字样式或平台资源；不能直接把px数字拷贝成pt/dp。

给组件定义用途、内容、状态、输入反馈和必要变体：按钮的默认/按下/焦点/禁用/忙碌，表单的标签/帮助/错误等。不是每个组件都需要所有变体。页面模式是多个组件为任务形成的关系，不应将一次页面布局变成万能模板。

新增Token前看是否已有等效角色；同值不同义可以分开，同义散落值可以统一。修改共享变量先查实际消费者和代表状态，避免为了一个页面让其他界面退化。参数确认后留下实际值、条件与使用位置，不能停留在抽象审美描述。


## 界面文字与品牌语气

先统一对象和动作的称呼，再写标题、按钮、帮助与错误。品牌语气可以稳定，失败、权限与数据风险的表达应具体平实。多步流程区分继续、保存草稿、正式提交与完成；空态给下一步，但长期重要说明不能只藏在稍后消失的空态中。格式示例不替代持续可见的字段标签。

错误要说明已知结果、影响及可行下一步。例：“调整尚未保存，库存未变”只有在确知未写入时才成立；结果不明就不能为了安慰用户这样写。若同一错误反复发生，检查流程和控件，别只增加文字。中文沿实际表达处理，不照抄英文大小写、字数或例子中的字段校验。[Writing](https://developer.apple.com/design/human-interface-guidelines/writing)

品牌可通过内容、图像、文字角色和关键时刻体现。工具型页面的内容优先不意味着展示型页面必须弱化品牌。系统启动过渡与正式欢迎/教学内容不同，后者按用途设计并允许合理退出；不为展示标志强行延长启动。[Branding](https://developer.apple.com/design/human-interface-guidelines/branding)

## 大字、主题与资源的实际变化

字体放大时允许行高增长、横排转纵排、列数减少，保留关键对象与动作；不再缩小字体抵消用户设置。使用自定义字体时补齐系统文字样式原本承担的缩放能力。macOS与iOS的文字放大机制并不相同，不能宣称设置同一文字角色就自动获得所有平台的Dynamic Type行为。[Typography](https://developer.apple.com/design/human-interface-guidelines/typography)

对支持的外观检查运行中主题切换、提高对比度、降低透明度及相关组合。系统语义色按用途选，不因某个当前色值好看就用分隔线颜色画正文。暗色重新建立底层与浮层关系；商品与证据图不因主题切换而擅自改色。默认跟随系统通常更省事；确有阅读或跨设备偏好时，可提供清楚的应用内覆盖项，不把Apple原生的独立主题建议扩大为全平台禁令。[Color](https://developer.apple.com/design/human-interface-guidelines/color) · [Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode)

界面图标与应用图标分开制作。前者关心动作语义、状态、字重和辅助名称；后者关心跨尺寸品牌识别及目标平台的蒙版、分层、外观。系统会加的效果不要重复烘焙。采用SF Symbols时核所需变体、最低系统版本和具体符号限制；多层/多色效果在小尺寸可能损失辨识，变量渲染不能假装真实进度。[Icons](https://developer.apple.com/design/human-interface-guidelines/icons) · [App icons](https://developer.apple.com/design/human-interface-guidelines/app-icons) · [SF Symbols](https://developer.apple.com/design/human-interface-guidelines/sf-symbols)

图像按展示尺寸、密度、色域、细节任务和传输成本选资源。缩略图用于识别，详情图用于看细节；放大低清图不会增加事实。透明边缘在深浅背景都要看，关键色彩需检查目标设备表现；Apple原生格式建议不能变成Web图片格式的统一规定。[Images](https://developer.apple.com/design/human-interface-guidelines/images)

空间平台的窗口材质还承担环境感知；普通业务Web的稳定底色方法不直接推广为空间应用的大面积不透明背景。材质应遵循目标平台职责并验证真实背景变化。[Materials](https://developer.apple.com/design/human-interface-guidelines/materials)
