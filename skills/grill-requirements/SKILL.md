# 需求榨干

先查清背景事实，再把真正需要用户拍板的决策逐个问透。达成共同理解前不实施；确认问答结束后，生成完整规划，不把规划自动升级为执行授权。

## 不可破坏的原则

- 默认一次只问一个会改变方案的问题，等待用户回答后再继续。当 2–3 个问题已确认互相独立、同属低风险同一层级、且合问不会削弱推荐理由或决策记录时，允许合并为一个“小批次”，并要求逐项作答。高影响或存在依赖关系的问题不得合并。
- 每题都给出明确的推荐答案和简短理由，不把所有分析成本推给用户。
- 优先查当前对话、项目文件、现行规则、本地环境和可用工具。能查到的事实不反问用户；只追问会改变结果的决策。
- 用正文的 `1 / 2 / 3` 选项提问，不使用点选、填框等交互组件。选项要互斥且真实，不制造假选项。
- 按依赖顺序解决决策。上游问题未定时，不急着询问会被它改写的下游细节。
- 直接指出冲突、隐含假设、过度设计和低回报需求；先审问题是否成立，不默认所有想法都应该实现。
- 允许用户回答“不知道”“以后定”或自定义答案。将它们分为必须在实施前解决、可在某阶段再解决、可安全默认三类。
- 不要为了“事无巨细”机械询问不适用的类别。要求是没有未暴露的重要分支，不是问题数量最大化。
- 不要展示隐藏思维链。只说用户需要判断的事实、取舍、推荐和理由。

## 工作流程

### 1. 定义访谈对象

用一小段话复述当前理解，只包含：

- 要解决的真实问题；
- 预期最终产物；
- 已知边界与当前不执行的范围；
- 已发现的最大不确定点。

如果连访谈对象都无法确定，把第一题用于确定对象。否则直接进入最高影响的未决问题。

### 2. 先查事实

在提问前检查相关上下文。项目任务先读项目入口、现行真相源、推进状态和实际文件；外部事实若时效性或准确性会影响选项，先查权威来源。

将获得的信息分为：

- `已确认事实`：可由当前证据直接支持；
- `待验证判断`：有根据但未足以确认；
- `用户决策`：没有唯一事实答案，必须由用户取舍。

不要把前两类伪装成第三类问给用户。

### 3. 建立决策树

按任务实际情况选取分支，不强制全部覆盖：

1. 问题是否成立，成功意味着什么；
2. 使用者、利益相关者与决策权；
3. 范围、明确不做事项与优先级；
4. 当前流程、现行真相源与主要断点；
5. 理想主流程、例外、失败与恢复分支；
6. 角色、权限、审批和通知；
7. 数据来源、字段口径、更新方式与质量标准；
8. 产物、界面、报表、文档或对外表达；
9. 依赖、集成、迁移、兼容与回滚；
10. 成本、时间、注意力、安全、合规和其他约束；
11. 阶段划分、停车闸、验收证据与失败兜底；
12. 交付后的所有权、维护、监控和退役。

优先解决会使方案改道、重做或带来高风险的问题，再处理局部偏好。

### 4. 执行追问循环

每轮使用这个结构：

```text
问题 N · [决策主题]

[一句话说明这个决策会影响什么]

1. [选项一]（推荐）
2. [选项二]
3. [选项三]

我推荐 1：[简短理由和主要取舍]。

请回复 1 / 2 / 3，也可以直接说你的答案。
```

根据问题使用 2–3 个真实选项；必要时可以不列选项，但仍要给推荐答案。

使用“小批次”时，每题仍须分别编号、说明影响、给出互斥选项和推荐理由；收到回答后逐项确认、逐项记入决策账本并分别检查冲突，不得因合问省略任何单题步骤。

收到回答后：

1. 用一句话确认刚得到的决策；
2. 更新对用户真实问题、核心动机、最终目标、成功标准、范围和关键约束的整体理解；
3. 将决策、理由、影响和状态记入当前决策账本；
4. 检查新回答是否推翻旧假设、产生新分支或与旧答案冲突；
5. 优先追问最可能改变上述理解、导致方案改道或显著降低理解不确定性的下一个问题。

在阶段转换、用户更改旧答案或决策较多时，给一次简短的阶段小结，避免用户忘记已定内容。

### 5. 关闭决策树

只在同时满足以下条件时建议结束访谈：

- 高影响分支已经确定或明确延后到某个停车闸；
- 目标、范围、不做事项和优先级没有重大矛盾；
- 主流程、关键异常和失败兜底已被覆盖；
- 依赖、风险、权限和高影响动作的确认闸已经暴露；
- 有可观察的完成标准和验收证据；
- AI 对用户真实问题、核心动机、最终目标、成功标准、范围和关键约束的整体理解，自评达到至少 95%；
- 对真实需求和目标不存在已知的高影响歧义；
- 剩余未决项不会让当前规划根本改道。

`95%` 是停止追问前的明确自评阈值，不要求把它伪装成可精确计算的数学概率，也不得因“已经有可行方案”或“已经问了很多轮”而降低标准。未达到时继续追问，并继续按默认单题与受控小批次条件判断。

然后输出一份“共同理解摘要”，只列目标、范围、关键决策、停车闸、验收口径和仍存的低影响未决项。最后只问一题：

```text
我判断高影响分支已经问透，对你的真实需求和目标的理解自评已达到至少 95%。

1. 确认共同理解，生成最终详细规划（推荐）
2. 继续追问我指定的部分
3. 继续自由压力测，直到你也找不到重要遗漏
```

用户选择 2 或 3 时继续追问循环。

### 6. 生成最终详细规划

用户确认共同理解后，完整读取 [references/final-plan-template.md](references/final-plan-template.md)，并按它生成最终规划。

规划必须：

- 完整保留已确认的决策和理由；
- 明确区分事实、用户决策、AI 建议、假设和未决项；
- 将“事无巨细”理解为完整、可追溯、无隐藏分支，而不是重复、堆字或虚构细节；
- 让每个阶段都有输入、动作、产物、停车闸和验收证据；
- 对不适用的类别标明“不适用及原因”，不用想象出来的需求填空；
- 以一个单独的“执行授权状态”收尾，明确规划完成不等于获得实施授权。

## 与其他 Skill 的边界

- 本 Skill 负责把需求问透并形成规划；不在问答结束前生成假完整方案。
- `/提示词增强` 负责整理用户已经表达出来的需求，不负责长时问答挖掘未表达需求。
- 实施、落盘、发布或写入外部系统属于后续任务，仍遵守当前项目授权和硬边界。
