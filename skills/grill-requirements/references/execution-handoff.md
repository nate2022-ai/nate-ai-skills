# 正式任务交接与终验

## 1. 先区分执行授权与另开任务授权

用于已明确要求的正式任务创建、跟进与终验；用户询问另开方式时可说明选项。模式和授权沿用已加载的主入口，准备执行者输入时使用入口选定的任务书模板。

- 只有用户明确要求另开正式任务，或明确选择包含创建新任务的选项，才进入下文独立任务流程。仅说“给另一个 agent 写任务书”是文本请求，不是创建授权；明确要求另开但未要求 Goal 时，直接采用普通正式任务，不重复询问执行方式。
- 同一批次已经有获授权的独立执行任务时，对同一批准分工继续跟进已有任务，不重复创建，也不改由原需求对话并行实施。不同分工须分别核对是否已获明确授权。同批授权、一次性操作及新增风险沿用主入口“已有授权的沿用”。

仅当用户询问另开任务的执行方式时，可展示以下选择；用户已经明确执行方式或只要文本时不强制展示：

1. 确认执行，并授权适合时在新正式主任务启动 Goal；
2. 确认执行，但只创建普通正式主任务；
3. 暂不执行。

上述菜单中只有明确选择 1 才包含 Goal 评估授权，仍不强制创建 Goal；用户直接明确要求“另开任务并使用 Goal”具有同样的授权含义。选择 2 只创建普通正式主任务。选择 3 或本次仍只要求研究、生成文本时不实施；出现实际授权缺口时只暂停受影响动作。

## 2. 创建真正的同级正式主任务

获得明确另开任务授权、且该批准分工尚无已创建的执行任务后，使用当前 Codex 正式 task/thread 能力创建一个用户可见、可重新进入、与原需求对话同级的新任务。按已确认规划准备执行者所需的任务书；已有完整任务书则直接复用，不重复索要同批次执行授权。禁止使用 fork、subagent 或内部协作代理冒充正式主任务，也不要另建临时验证任务或为同一已批准分工重复创建执行任务；用户明确批准不同分工的多个正式任务时，逐项按批准范围处理。

- 有项目归属时，先读取正式项目列表并绑定正确项目；无项目归属时才使用 projectless。
- 按项目状态选择 Local 或 Worktree，并向用户披露选择理由。Git 项目通常优先 Worktree；用户明确要求当前检出、任务依赖未提交现场或 Worktree 无法保持所需基线时，选择 Local，并核对同一实际修改范围没有其他写入者。
- 创建完成后记录真实 `threadId` 和 `hostId`，并从正式任务列表核对它可发现、可重新进入。若 Worktree 仍只返回 `clientThreadId`，等待物化为真实 `threadId` 后再执行后续读取或等待。

新任务必须收到最终任务书、用户本次授权、项目与环境选择、允许修改白名单、禁区、验收命令和结构化回执格式；必要的未公开抽查样例由验收方保留。

## 3. 判断 Goal 是否适合并执行安全降级

本节仅适用于已获另开任务授权的路径。只有明确请求在新任务使用 Goal（含选择 1），且以下条件全部成立，才判定适合 Goal：稳定目标、多步骤、可在授权范围内自治、明确完成标准、所有实施与高风险闸门关闭。

出现任一情况就不适合：一次性或很短的动作、仅规划或研究、频繁需要用户决策、高风险动作未授权、平台能力未经验证、不能独立闭合。此时自动降级为一个普通正式主任务，简要说明具体理由，不再让用户在 Goal、普通任务、fork 或 subagent 之间做技术选择。

若正式任务可发现性、Goal 能力、结果回流或独立验收出现回归，关闭受影响的 Goal 路径并安全降级为普通正式主任务；以当前能力与证据判断。

Goal 路径仍须先创建正式主任务，再在新正式主任务内部调用真实 Goal 能力并立即读取真实状态；回执至少记录工具实际返回的任务或 Goal 标识、objective 和状态；绑定关系以当前工具返回为准。若工具没有返回独立 Goal ID，必须如实写“独立 Goal ID：无”，不得编造。原需求对话的 Goal 创建数必须为 0；仅出现“Goal”或命令文字不算真实运行证据。

## 4. 原需求对话负责回流与终验

默认由原需求对话承担整体责任；用户明确移交总责时，以下回流与终验责任随现行承接方转移，原任务不再并行实施或成为已取消的等待依赖。不能仅凭另一个任务自称接手就改换责任方。

原需求对话按需要使用正式任务的等待与读取能力跟进 `threadId` 与 `hostId`，保留有用的等待。当前无可推进的已授权工作、后续接续方式清楚时，可以结束本轮，并说明未完事项及实际接续方式；结束本轮不代表整体完成，也不默认要求执行任务主动回报。

若执行者请求确认，先按主入口“已有授权的沿用”核对。仅为同义重复确认时传递已有授权并继续；确有新增授权缺口、越过白名单或触发停车闸时暂停受影响动作交给用户，不代替用户批准。工具权限受阻时，先定位具体限制并继续不受影响的工作，只把必要的人工作业交给用户。

任务返回后，原需求对话按风险核验关键证据与共同使用结果；有证据缺口时补充独立检查，已有可靠证据直接复用。必要、安全、可重复且仍在授权内的检查应亲自复跑；真实发送等一次性或不可重复操作通过结果回读核验，不为验收重复执行。执行者自报成功、自己的测试绿灯或结构化回执不能替代终验；必要验收或有效抽查失败时不得判通过，证据不足时明确未验证项。

最终简明说明通过与否、实际完成、关键证据、遗留问题和必要的下一步，篇幅服从信息需要。原需求对话负责正式判定，执行者不得自判终验通过。
