# 长任务接续

预计跨多轮、多阶段或跨上下文的任务，在生成规划或任务书、以及讨论后直接转入已授权执行时适用。不强制输出完整长文、另开任务或新建记录；具体方法由执行者选择，以下动作合并进已有承接、验证与接续过程。

1. **固定任务依据**：保留目标、范围、不做事项、已确认决定及理由、AI 默认、验收标准、未决条件及来源。一个总目标可以包含多个必交结果；每项对应阶段、关键约束和验收证据，反查全部已确认需求是否被遗漏、曲解或扩展。优先级较低不等于可以省略，不把 AI 建议写成用户确认。
2. **记录与接续**：指定唯一接续位置，复用所属项目已授权的状态或推进机制，记录实际完成与证据、剩余工作、阻塞和下一接续点。执行入口携带有效任务依据与记录位置；首次执行或恢复时核对依据、进度和现场，不凭聊天摘要重规划，不重复已有证据的完成项。已读且未变的内容直接复用，缺失或变化时定向补读；不增加每阶段全文重读或第二套主进度。研究阶段在文本中维护，未经写入授权不落盘；必要持久化条件未具备时明确说明，不能宣称已可跨上下文可靠接续。
3. **阶段验证与整体完成**：阶段交付核本阶段结果及其影响到的其他必交结果、关键约束和已完成成果，只补必要验证。宣布整体完成前，对照全部有效必交结果核实证据，并验证适用的共同使用结果；子项通过不等于整体可用。未完成、待验收以及获批取消或延后的事项分别说明，不混记为完成。仍有原授权内可完成的漏项时继续处理，不把局部完成代替总任务完成。
4. **控制变更**：新信息先区分事实补充、实施调整、目标变更和规则冲突。实现细节可在授权内调整；目标、范围、关键约束或验收标准变化，须说明影响并由用户决定，实施须有明确授权。保留变更的决定、理由、来源与影响，不得以宣布完成为由降低验收。更晚相反决定或新的规则冲突，按主入口“规则冲突：按影响暂停与接续”处理。

规划或任务书携带以上必要依据与承接要求，不能只留在生成者记忆中。日常仅报告结果、重要变化和待决定事项，不重复展示完整检查过程。
